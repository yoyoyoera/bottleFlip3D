# Bottle Flip 3D — 기획서 v0.1

> 한 줄 요약: **4명이 한 테이블에 둘러앉아 물병을 던져 세우는 물리 파티 게임.**
> 규칙 설명이 필요 없고, 성공은 짧고 확실하며, 실패는 웃기다.

---

## 1. 핵심 원칙 (모든 결정의 기준)

1. **손맛이 먼저.** 던지는 조작이 재미없으면 유체도, 맵도, 멀티도 의미 없다. 모든 마일스톤은 "직접 100번 던져보고 재밌는가"로 통과 여부를 정한다.
2. **유체는 "게임플레이 물리"와 "보이는 유체"로 나눈다.**
   - 게임플레이: 병 안의 가벼운 입자 몇 개(대리 모델)로 무게중심, 출렁임, 착지 흡수를 계산한다. 결정적이고 가볍다.
   - 시각: 수면, 거품, 색은 각 클라이언트가 로컬에서 그린다. 동기화하지 않는다.
3. **커스터마이징은 외형보다 성능 차이.** 병/유체/채운 양의 선택이 곧 전략이다. 색이나 포장지는 그다음이다.
4. **맵은 에셋보다 규칙으로 변주한다.** 마찰, 중력, 흔들림만 바꿔도 같은 손동작이 다르게 먹힌다.
5. **멀티는 단계적으로.** 턴제(번갈아 던지기)부터 시작한다. 한 번에 한 병만 날아가니 동기화 부담이 거의 없다.

## 2. 조작 (1인칭): "병 옮기기 → 스크롤로 각도 → 위로 끌어 힘 → 놓기"

시점은 **1인칭**이다. 내 자리(테이블 앞쪽 의자)에 앉은 눈높이에서 테이블을 내려다본다.

| 입력 | 결과 |
|---|---|
| 마우스 이동 | 손에 든 병이 커서를 따라 테이블 위를 움직인다. 빠르게 옮기면 물이 출렁인다 |
| 스크롤 (↑/↓) | **던지는 각도 0~20°**. 기울일수록 멀리 가지만(목표 원 조준) 앞으로 나가는 속도 때문에 착지할 때 걸려 넘어지기 쉽다 |
| 누른 채 위로 끌기 | **끈 거리 = 힘**. 병이 조금씩 들리고 파워 미터가 찬다 |
| 놓기 | 던지기 (거의 안 끌었거나 우클릭/Esc면 취소) |

- 처음에는 플릭 속도로 힘을 정했는데, 드래그 거리 방식으로 바꿨다. 속도는 손마다 편차가 커서 원하는 만큼 정확히 주기 어렵다. 거리 방식이면 조절이 되고, 대신 "구간을 기억하는" 실력이 중요해진다.
- 예상 궤적(점선)과 착지 예상 지점(노란 원)을 보여준다. 도전 모드에서는 이걸 숨겨 난이도를 올릴 수 있다.
- 회전은 `기본 회전 + 위 속도 × 비례값`으로 정한다. 세게 던지면 높이 뜨고 조금 더 돈다. 프로토타입 테스트 결과, 회전이 힘에 전부 비례하면 성공 구간이 너무 좁았다(파워 범위의 약 5%). 기본 회전을 크게 두고 비례분을 작게 하니 구간이 약 12%로 넓어졌다.
- 각도별 측정(물 30%, 기본 병): 0~6°에서 성공 구간이 가장 넓고, 12°에서 좁아지며, 20°부터는 거의 서지 않는다. **각도 = 위험과 보상의 선택**이다.
- **숙련 요소:** 병, 유체, 채운 양, 맵, 각도마다 성공하는 파워 구간이 다르다.
- 보조 입력: **Space 길게 눌러 충전**(0에서 최대까지 왕복). 트랙패드나 모바일용.

## 3. 게임 모드와 루프

### 기본 루프 (한 턴)
`내 차례 → 준비 동작(드래그) → 플릭 → 비행(약 0.6초) → 착지 판정 → 리액션/점수 → 다음 사람`

### 판정
| 결과 | 조건 | 점수(안) |
|---|---|---|
| 성공 | 멈췄을 때 병 축이 수직에서 약 14° 이내 | +1, 연속 성공 시 콤보 |
| **뚜껑 착지** | 거꾸로 섰을 때 | +3 (하이라이트 연출) |
| 쓰러짐 | 그 외 | 0, 콤보 끊김 |
| 테이블 밖 | 테이블 밖으로 떨어짐 | 0 (웃긴 리액션) |

### 모드 (단계별)
1. **연습:** 혼자 무한 던지기, 성공 구간 가이드 표시 (프로토타입에 구현됨)
2. **파티 턴제 (MVP 멀티):** 최대 4인이 번갈아 던진다. 라운드마다 테이블 위 목표 원의 위치가 바뀌고, 원 안에 세우면 보너스.
3. **챌린지 룰 (라운드마다 랜덤):** "꿀만 사용", "빈 병 50%", "목표 원이 점점 멀어짐", "뚜껑 착지만 점수" 등. 적은 에셋으로 반복 플레이 가치를 만든다.
4. **고스트 기록전:** 비동기 경쟁. 결정적 시뮬레이션이라 입력(파워, 좌우, 시드)만 저장하면 리플레이를 재생할 수 있다.
5. (후순위) 실시간 동시 던지기: 병끼리 부딪히는 혼돈 모드. 동기화 비용이 크니 마지막에 한다.

## 4. 커스터마이징: 성능 차이 먼저

### 병
| 병 | 특징 | 트레이드오프 |
|---|---|---|
| 미니 페트 330ml | 가볍고 민감 | 성공 구간이 좁고 채운 양에 따라 크게 달라진다 |
| 기본 페트 500ml | 기준 | 가장 무난하다 |
| 대형 페트 1.5L | 무겁고 느긋 | 세게 던져야 하지만 구간이 넓다 |
| 유리병 | 병 자체가 무거워 유체 효과가 작다 | 하드 모드, 성공 시 보상 큼 |

### 유체 (게임플레이 대리 모델 파라미터로 차별화)
| 유체 | 밀도 | 점성 | 특수 | 플레이 느낌 |
|---|---|---|---|---|
| 물 | 1.0 | 낮음 | – | 기준. 공중에서 길게 퍼져 회전이 느려지고, 착지 때 철퍽 흡수 |
| 꿀 | 1.4 | 높음 | 착지 흡수 큼 | 회전이 빨리 죽어서 세게 던져야 한다. 대신 성공 구간이 넓고 묵직하다 |
| 탄산 | 1.0 | 낮음 | 착지 시 거품 반동 (시드 기반 랜덤) | 물과 비슷한데 가끔 배신한다. 거품 연출 |
| 슬라임 | 1.1 | 중간 | 벽 반발 | 착지가 통통 튀는 도박형 |
| (후보) 모래 | 1.6 | 마찰 큼 | 입자끼리 마찰 | 출렁임 없이 착지가 안정적인데 회전 감속이 약하다 |
| (후보) 얼음 조각 | 0.9 | 없음 | 착지 시 딸그락 튐 | 예측 불가 |

### 채운 양 (0~100%)
실제 물병 던지기처럼 **1/3 근처가 가장 쉽다.** 프로토타입 측정 결과(물, 기본 병) 30%에서 성공 구간이 가장 넓고, 50%는 매우 어렵고, 빈 병은 거의 불가능했다. 이걸 튜토리얼에서 발견하게 만들면 "아는 사람만 아는" 재미가 된다.

### 외형 (성능에 영향 없음)
- 유체 색소 (물, 탄산)
- 포장지 패턴 + 색
- 뚜껑 색
- (후순위) 스티커, 착지 이펙트, 병 트레일

> 외형은 수익화(스킨 DLC)나 업적 보상으로 쓰기 좋다. 성능 아이템은 모두 기본 제공해서 페이투윈 논란을 피한다.

| (후보) 회전초밥 레일 | 목표 지점이 움직임 | |
| (후보) 흔들 테이블 | 한쪽 다리가 짧아서 기울어짐 | |

## 7. 기술 구조

### 7.1 물리 (프로토타입에서 검증함)
- **병:** 강체 1개. 테이블과의 충돌은 바닥 링, 어깨 링, 뚜껑 링의 충돌점으로 처리한다.
- **유체:** 병 안에 갇힌 입자 3~20개. 채운 양에 비례한다.
  - 입자와 내벽 사이, 입자끼리 접촉 (부피 유지)
  - 점성: 병 벽 속도 쪽으로 끌어당기는 결합
  - 착지 흡수(absorb): 착지 직후 0.15초 동안 계 전체의 상대 운동(회전 포함)을 줄인다. 실제 "철퍽" 효과를 게임적으로 강조한 튜닝 값이다.
- **솔버:** 고정 타임스텝 1/240초, 순차 충격량 12회 반복, 스펙큘러티브 접촉.
- **결정성:** 같은 입력(파워, 좌우, 시드) → 같은 결과. 테스트로 보장한다.
- 이 구조 덕분에 실제로 일어나는 현상:
  - 공중에서 물이 병 길이 방향으로 퍼짐 → 관성모멘트 증가 → **회전속도가 약 1/3로 감소** (실제 물병 뒤집기의 원리)
  - 빈 병은 회전이 유지되어 거의 서지 않음

### 7.2 시각 유체
- 입자 무게중심으로 수면의 방향과 높이를 추정하고, 클리핑 평면으로 병 안의 액체 메쉬를 자른다.
- 탄산 기포와 착지 거품은 순수 연출이다.
- 정식 버전에서는 셰이더 기반 출렁임(wobble)이나 로컬 SPH/FLIP으로 교체해도 된다. 게임플레이에는 영향이 없다.

### 7.3 네트워크 (단계별)
1. **턴제:** 던지는 사람 = 권한자. 입력(파워, 좌우, 시드)을 먼저 뿌리고, 이어서 병의 위치와 회전 스냅샷을 20~30Hz로 전송한다. 다른 클라이언트는 보간해서 재생한다. 판정은 호스트가 확정한다.
2. 부동소수점은 기기마다 미세하게 다를 수 있어서, **입력만 보내고 각자 시뮬레이션하는 방식(록스텝)은 판정에 쓰지 않는다.** 대신 로컬 즉시 미리보기나 리플레이 용도로만 쓴다.
3. 방 코드 매칭: Steam Lobby(스팀 출시 시) 또는 Relay 서비스(Unity Relay, Photon 등).

### 7.4 엔진
- **지금:** 웹 프로토타입(Three.js + 자체 물리). 설치 없이 바로 던져볼 수 있고 링크로 공유하기 쉽다. 손맛 검증 전용이다.
- **정식 추천: Unity.** 물리 코어는 엔진 물리(PhysX)를 쓰지 않고 이 프로토타입의 자체 솔버(약 500줄)를 C#으로 이식한다. 결정성과 튜닝을 그대로 가져갈 수 있다. 렌더링, UI, 스팀 연동(Steamworks.NET), 네트워크(Netcode/Mirror/Photon)는 Unity 생태계를 활용한다.
- 대안: 웹 그대로 가서 Electron/Tauri + steamworks.js로 스팀에 출시하는 방법. 1인 개발이면 이식 비용 없이 바로 확장 가능하지만, 그래픽 퀄리티의 상한과 스팀 연동 성숙도 면에서 Unity가 안전하다.

## 8. 로드맵

| 단계 | 목표 | 통과 기준 |
|---|---|---|
| **M0 손맛 프로토** ✅ (이 레포 `prototype/`) | 병 4, 유체 4, 맵 4, 플릭 조작, 성공 구간 가이드 | 직접 100번 던져서 "한 번만 더"가 나오는가 |
| M1 조작 확정 | 플릭 감도, 회전 공식, 착지 흡수 튜닝 확정, 효과음/진동/카메라 연출 | 처음 해보는 사람 5명 중 4명이 10번 안에 첫 성공 |
| M2 로컬 파티 | 핫시트 2~4인 턴제, 점수, 콤보, 챌린지 룰 | 친구끼리 30분 동안 계속 플레이 |
| M3 엔진 이식 판단 | Unity로 물리 코어 이식, 결정성 테스트 이식 | 웹판과 같은 입력 → 같은 판정 |
| M4 온라인 4인 | Host/Join 방 코드, 턴제 동기화, 재접속 | 핑 150ms에서도 어색하지 않음 |
| M5 콘텐츠 | 맵 6~8, 유체 6, 외형 커스터마이징, 업적 | – |
| M6 출시 준비 | 스팀 페이지 → 위시리스트 → 넥스트 페스트 데모 | 트레일러용 "뚜껑 착지" 클립 확보 |

> 스팀 페이지는 M2~M3 무렵에 일찍 연다. 쇼츠, 클립용으로 **리플레이 저장과 슬로모션 공유 기능**은 M5 안에 꼭 넣는다. 이 장르는 바이럴이 핵심 마케팅이다.

| 조작이 재미없다 | M0/M1에서 튜닝 슬라이더로 빠르게 반복한다. 재미가 없으면 여기서 방향을 튼다 |
| 성공 구간이 너무 좁거나 넓다 | 결정적 시뮬레이션으로 파워별 결과를 자동 측정(`guide`)해서 조합별 난이도를 수치로 관리한다 |
| 유체 연산 비용 | 게임플레이는 입자 20개 이하라 무시할 수 있는 수준이다. 시각 효과는 품질 옵션으로 조절한다 |
| 멀티 동기화 | 턴제와 권한자 스냅샷 방식이라 동시 물리가 없다 |
| 반복 플레이 부족 | 챌린지 룰, 맵 규칙, 고스트 기록전, 외형 수집 |
